Avant tout

Cette page ne garde rien en mémoire : si tu la fermes, les cases se vident. Utilise le bouton Copier les anomalies en bas avant de fermer, et colle le résultat dans la conversation.

Page prévue pour être ouverte depuis son adresse web, y compris sur téléphone : un fichier enregistré en local n'exécute pas les scripts, le compteur et le bouton de copie resteraient inertes.

Critères d'arrêt immédiat

On interrompt la recette et on diagnostique avant de continuer si l'un de ces trois signaux apparaît : une donnée réelle disparaît sans qu'on l'ait demandé · un MAR autre que toi reçoit un email · une page reste blanche sans message d'erreur. Tout le reste se note et se poursuit.

P0Prérequis

À faire dans l'ordre. Ce ne sont pas des tests : c'est le filet.

  1. Sauvegarde du classeur maître. Fichier → Créer une copie, nommée SAUVEGARDE-AVANT-RECETTE-2026-08-01, rangée sur ton compte perso. Non négociable : la phase 10 supprime des onglets.
  2. Contrôle de version. admin.html → onglet Maintenance → 🔍 Diagnostic. Aucune ligne ne doit signaler de désynchronisation entre le dépôt et le déployé. Si une recopie manque, fais-la maintenant : sinon tu testeras un code différent de celui que je lis.
  3. État de départ, noté sur papier. Dans CONFIG : valeur de ANNEE_ACTIVE (attendu 2027) et de INDISPOS_ACTIVE. Dans le classeur : la liste des onglets présents. C'est ta référence pour le nettoyage final.
  4. Classeur d'archive. Ouvre-le et vérifie s'il contient déjà STATS_GARDES_2027. Si oui, note-le : la clôture l'écrasera sans prévenir.
  5. Emails. Tu confirmes que seule ton adresse est renseignée dans MEDECINS. Recompte-le une fois, ligne par ligne, avant la phase 10 : c'est le seul point où une erreur touche l'équipe.
  6. Console ouverte. F12 → onglet Console, gardée ouverte toute la séance. La moitié des anomalies s'y voient avant de se voir à l'écran. Note toute ligne rouge.
  7. Un seul onglet du portail ouvert, sauf quand un test demande explicitement le contraire.
  8. Rechargement forcé (Ctrl+Maj+R) sur chaque page au moment où tu l'ouvres pour la première fois.

P1Accès et rôles

Trois rôles existent côté serveur : admin, mar, secretariat. Le secrétariat a une liste blanche de deux actions seulement, tout le reste lui est refusé par défaut.

T001
Ouvrir admin.html et se connecter avec le code comité.
Attendu : l'écran s'ouvre, l'année 2027 s'affiche en en-tête, aucune erreur en console.
T002
Ouvrir dashboard.html avec ton code MAR personnel.
Attendu : ton prénom/tes initiales apparaissent, les tuiles se dessinent.
T003
Ouvrir absences.html avec le code du secrétariat.
Attendu : la liste des MARs à consulter s'affiche. Aucun code d'absence ne doit être visible — seulement des dates. C'est la règle « dates seules ».
T004
Saisir un code inexistant (ex. ZZZZ99) sur dashboard.html.
Attendu : un message compréhensible, pas d'écran blanc, pas de « undefined ». Note le texte exact.
T005
Saisir un code vide, puis un code avec une espace avant et après.
Attendu : refus propre pour le vide ; le code entouré d'espaces doit fonctionner (les espaces sont nettoyés).
T006
Sur dashboard.html connecté avec le code d'un autre MAR (crée-toi un code de test si besoin), regarder les tuiles.
Attendu : les tuiles CRH, Guide technique et Libéral n'apparaissent pas (réservées à FROHLICH).
T007
Utiliser « Se déconnecter / changer d'utilisateur » sur le dashboard.
Attendu : confirmation demandée, puis retour à l'écran de code. Rouvrir la page ne doit pas reconnecter automatiquement.
T008
Session ouverte sur dashboard. Dans le classeur, modifier ton code d'accès dans MEDECINS. Cliquer ensuite sur une tuile qui charge des données.
Attendu : le refus arrive — immédiatement, ou après le bouton « vider le cache de configuration » de Maintenance. Note lequel des deux. C'est le délai réel de révocation d'un code.
T009
Remettre ton code d'origine et vérifier que tu te reconnectes.
Attendu : accès rétabli. Ne pas oublier cette étape avant de continuer.
T010
Depuis la session secrétariat, ouvrir la console (F12) et tenter une action interdite, par exemple demander la liste des médecins.
Attendu : refus du serveur. Le rôle secrétariat n'a droit qu'à deux actions ; toutes les autres doivent être rejetées, pas seulement masquées à l'écran.
T011
Ouvrir deux sessions dans deux navigateurs différents : toi en admin, toi en MAR.
Attendu : les deux cohabitent sans interférence. Une action dans l'une ne doit pas déconnecter l'autre.
T012
Se connecter, fermer le navigateur entièrement, rouvrir et retourner sur la page.
Attendu : comportement cohérent et explicable — soit la session persiste, soit le code est redemandé. Note lequel des deux, c'est ce que vivront les MARs.

P4Comité — planning quotidien

Le cœur d'admin.html, et la partie la plus récemment modifiée (sauvegardes groupées, préchargement des panneaux). Tout se passe sur ton 2027 de test.

T033
Ouvrir l'onglet Planning et taper chrono() dans la console après le chargement complet.
Attendu : budget d'ouverture affiché. Note le total — il servira de référence pour comparer après les tests de charge.
T034
Placer un MAR dans une case vide, puis vérifier dans le classeur.
Attendu : la ligne apparaît dans PLANNING_OVERRIDES avec la bonne date et le bon MAR.
T035
Faire dix placements d'affilée rapidement, puis taper chronoAPI().
Attendu : les écritures sont groupées (savePlanningOverridesBatch), pas dix appels séparés. C'est l'optimisation récente : c'est le moment de vérifier qu'elle tient.
T036
Retirer un placement posé au test précédent, puis regarder PLANNING_OVERRIDES.
Attendu : le MAR redevient volant à l'écran. La ligne ne disparaît pas forcément du classeur : elle prend la valeur VOLANT, nécessaire pour écraser son affectation de base. Ce n'est un défaut que si l'écran et le classeur se contredisent.
T037
Placer un MAR sur un jour où il est en vacances ou de garde.
Attendu : le MAR n'est pas proposé du tout — le conflit est empêché plutôt que signalé. S'il apparaît malgré tout dans la liste, c'est un défaut.
T038
Placer le même MAR deux fois le même jour, matin et après-midi, sur deux secteurs différents.
Attendu : comportement cohérent et explicable. Note ce qui se passe exactement.
T039
Ouvrir le panneau de semaine, puis passer à la semaine suivante.
Attendu : le passage est quasi instantané (le panneau suivant est préchargé). Si tu attends plus de 2 s, note la valeur.
T040
Consulter la liste des MARs disponibles pour un jour donné.
Attendu : les MARs en congé, en garde ou en repos de garde n'y figurent pas. Vérifier deux cas contre le classeur.
T041
Ouvrir l'écran des conflits globaux.
Attendu : la liste correspond aux conflits réellement présents. En créer un exprès et vérifier qu'il apparaît.
T042
Modifier un statut quotidien (setDailyStatus) sur un jour.
Attendu : effet visible dans index.html après rechargement.
T043
Publier le planning.
Attendu : succès affiché, et planning_2027.json mis à jour sur le Drive (vérifier l'horodatage du fichier).
T044
Après publication, attendre 10 minutes sans rien toucher.
Attendu : la notification par email part — chez toi uniquement. C'est le mécanisme d'accalmie de 10 min. Vérifie que le contenu du mail décrit bien les changements réels.
T045
Poser un changement, puis l'annuler avant la fin des 10 minutes, et republier.
Attendu : aucun mail ne part pour un changement posé puis retiré. C'est une garantie annoncée dans le code : elle mérite d'être vérifiée en vrai.
T046
Poser une absence longue sur un MAR, vérifier le planning, puis l'annuler.
Attendu : la période entière bascule, puis revient à l'état d'origine sans résidu.
T047

Attendu : soit le placement est enregistré, soit il ne l'est pas — mais l'écran et le classeur doivent dire la même chose. Une divergence ici est grave.
T048
Exporter la semaine en Excel depuis admin.html, puis ouvrir le fichier.
Attendu : toutes les lignes de secteur et de consultation présentes, MARs corrects, en-têtes lisibles. C'est le fichier qui part au service : une ligne manquante est un défaut majeur.
T049
Ajouter une ligne dans l'onglet SECTEURS du classeur, vider le cache de configuration, recharger.
Attendu : le nouveau secteur apparaît dans la grille. Le retirer ensuite et vérifier qu'il disparaît.
T050
Modifier un chiffre dans l'onglet CS_TEMPLATE (par exemple deux consultations de viscéral le mardi après-midi au lieu d'une), vider le cache, recharger.
Attendu : la grille réclame bien le nouveau nombre. Remettre la valeur d'origine ensuite.
T051
Vider entièrement l'onglet SECTEURS, recharger admin.html.
Attendu : le bandeau orange apparaît et l'export Excel est bloqué — c'est volontaire, un fichier amputé ne doit pas partir. Restaurer l'onglet aussitôt.

T064

T065
Lancer l'assistant « départ » sur un MAR de test.

T066
Après le départ, vérifier la grille du planning et l'encadré « à placer ».
Attendu : le MAR ne figure plus dans les propositions ni dans les MARs à placer. C'est le correctif du 2 août — c'est le moment de vérifier qu'il tient.
T067
Poser une absence longue de trois semaines sur un MAR, vérifier le planning, puis la raccourcir.

P9Module libéral

L'estimateur (cotation, devis, déclaration) et le suivi des 30 %. La partie où une erreur de calcul coûte de l'argent réel.

T094
Coter un acte CCAM que tu connais par cœur et recalculer la base de remboursement à la main.
Attendu : tarif × 1,95 × (1 + %modificateurs) × taux d'association + modificateurs en euros. Écart toléré : zéro.
T095
Coter un acte NGAP et recalculer à la main.
Attendu : lettre-clé × coefficient, sans le 1,95 et sans modificateurs. C'est la confusion la plus facile à commettre.
T096
Coter une association de deux actes.
Attendu : taux d'association appliqué au bon acte (le second à taux réduit), pas aux deux.
T097
Ajouter un dépassement d'honoraires.
Attendu : le dépassement s'ajoute au total facturé mais reste hors du calcul des 30 %. Le plafond ne porte que sur la base de remboursement.
T098
Chercher le code APC.
Attendu : il ne doit pas être proposé comme valide — il n'existe pas dans la nomenclature monégasque.
T099
Générer et imprimer un devis.
Attendu : montants cohérents avec l'écran, mise en page imprimable, mentions correctes.
