Déménagement NCHPG

La bascule des secteurs — document de travail pour l'administrateur · janvier 2027.

Il complète le §18 du guide technique (marche à suivre détaillée pour créer un secteur ou une consultation) : ici, on décrit le chantier du déménagement — quoi décider, quoi faire modifier dans le code, quoi faire soi-même dans le classeur, et dans quel ordre.

Créé le 06/08/2026 · organisation cible du NCHPG non connue à cette date — les encadrés violets ⏳ marquent ce qui reste à compléter.

L'idée en une phrase

Au NCHPG, les codes de secteurs changent complètement. On ne renomme rien : on crée les nouveaux secteurs dans le classeur, on désactive les anciens, et entre les deux, une (seule) série de modifications de code doit être livrée pour que les cases « à pourvoir » suivent le mouvement.

01Ce qui change · ce qui ne change pas

ChangeNe change pas
Les codes de secteurs et leur organisation : de grands secteurs (« Bloc long », « Bloc court »…) contenant des sous-secteurs (endoscopies, cardio…). Les gardes. Elles sont générées par année, indépendamment des secteurs. L'année 2027 est déjà générée : on n'y touche pas.
Les consultations, si leur découpage suit la nouvelle organisation. Les spécialités. Le module libéral est volontairement modélisé par spécialité et non par secteur, précisément pour survivre au déménagement. Rien à faire de ce côté.
Les affectations mensuelles (AFFECTATIONS_{Y}) : de la donnée, re-saisie avec les nouveaux codes à partir du mois de la bascule. Les MAR, leurs indisponibilités, leurs vacances, leurs codes d'accès.

02La règle d'or : un code ne se renomme jamais

Le code d'un secteur (VIS, ORT…) est écrit tel quel dans les affectations mensuelles, dans le planning publié et dans les placements du comité (PLANNING_OVERRIDES). Renommer un code en service rendrait tout cet historique orphelin — d'un coup, en silence.

La bascule se fait donc par ajout :

  • les nouveaux secteurs sont créés (nouvelles lignes, nouveaux codes) ;
  • les anciens passent ACTIF = N — la ligne est conservée, avec ses couleurs et libellés, pour l'historique.
Vérifié au banc (06/08/2026) — ACTIF = N efface l'historique de l'écran

Testé sur les vraies pages, avec un planning publié portant un secteur passé ensuite ACTIF = N : sur admin.html, la ligne du secteur disparaît de la grille — y compris pour les semaines déjà publiées — et un MAR placé dans ce secteur est ignoré silencieusement au rendu (l.≈3673 : pas de repli). Sur index.html, le secteur perd sa ligne, sa couleur et son libellé. Les données, elles, sont intactes : seul l'affichage est touché.

Conséquence pratique : ne désactiver les anciens secteurs que lorsque plus personne n'a besoin de consulter les semaines de l'ancien hôpital à l'écran — ou demander au lot de code (§04) d'apprendre au rendu à afficher un secteur inactif encore présent dans un planning publié. À trancher en Phase A.

03Phase A — Décider (dès que l'organisation cible est connue)

Rien de ce qui suit ne se code ni ne se saisit tant que ces décisions ne sont pas prises.

  1. La maille d'affectation. Aujourd'hui, un MAR est affecté au mois à un code de secteur, comparé tel quel partout. Avec une hiérarchie grand secteur / sous-secteur : est-on affecté au grand secteur ou au sous-secteur ? Cette réponse fixe la maille de tout le reste — couverture, panneau de placement, export Excel. C'est la décision structurante.
  2. La table de correspondance. Un tableau ancien code → nouveau(x) code(s), validé avec le service. Il servira à re-saisir les affectations et à relire l'historique.
  3. La règle de couverture par secteur. Pour chaque nouveau secteur : doit-il toujours être pourvu (donc déclencher un « + » clignotant quand il ne l'est pas) ? C'est une règle métier, pas une conséquence technique.
  4. Les règles fines à réexaminer. Trois exceptions sont aujourd'hui écrites en dur autour des anciens codes et devront être re-décidées dans les termes du NCHPG :
    • RI : hors couverture générale, requis mercredi et jeudi matin uniquement ;
    • CI : non requis le jeudi (jour de radio interventionnelle seule) ;
    • MAT : toujours pourvue, avec le miroir automatique vers sa consultation.
  5. La date d'effet. Les affectations sont mensuelles : basculer au 1er d'un mois, jamais en cours de mois. Attention, l'année de planning ne coïncide pas avec l'année civile (l'année 2026 court jusqu'au dimanche 3 janvier 2027).
  6. Les consultations. La liste des types de consultation au NCHPG, avec leurs créneaux par demi-journée.
⏳ À compléter quand l'organisation est connue

· Maille d'affectation retenue : …
· Table de correspondance : …
· Liste des secteurs couverts : …
· Date d'effet : …

04Phase B — Le lot de code (avec le développeur, avant la bascule)

C'est la seule partie qui ne se fait pas en autonomie dans le classeur. Un fil de conversation dédié, un lot, un banc au vert.

Le point le plus dangereux

Deux listes de secteurs sont encore écrites en dur dans admin.html : celle qui déclenche les « + » de case à pourvoir (COVERAGE, l.≈3754) et celle des boutons « Déplacer vers » (targets, l.≈4761). Tant qu'elles ne sont pas débranchées, un secteur créé dans l'onglet ne flashe jamais et n'a pas de bouton. Au NCHPG, ces listes deviendraient des codes morts : le signal de sécurité s'éteindrait partout, sans erreur ni message. Ce lot doit être livré et vérifié avant la bascule.

Contenu du lot (cadré le 30/07/2026)

  • Colonne COUVERTURE (O/N) dans l'onglet SECTEURS : la règle métier « ce secteur doit toujours être pourvu » sort du code et se règle dans le classeur. COVERAGE et targets lisent l'onglet.
  • Les règles fines (RI, CI-jeudi, mater) réécrites selon les décisions de la Phase A — elles aussi sont en dur aujourd'hui.
  • Colonne PARENT dans SECTEURS pour l'export Excel : un bandeau fusionné par grand secteur (option A, retenue le 30/07). Maquette validée en rendu PDF : maquette-export-excel-secteurs.xlsx.
  • Selon la décision prise au §02 : apprendre au rendu à afficher un secteur inactif encore présent dans un planning publié (aujourd'hui, sa ligne disparaît et ses placements sont ignorés à l'écran — constat vérifié au banc le 06/08/2026).

Chaque élément arrive avec son scénario de banc ; rien ne se pousse tant que tout n'est pas au vert, et le banc prouve la logique, pas l'infrastructure : la preuve finale reste l'essai en production sur une semaine réelle.

05Phase C — La bascule (classeur seul, aucun code)

Une fois la Phase B en production. Chaque geste est détaillé au §18 du guide technique — ici, l'ordre.

  1. Créer les nouveaux secteurs dans l'onglet SECTEURS : une ligne par secteur, avec ORDRE, CODE, libellés, couleurs, AFF (rempli = affectable au mois), colonnes Excel — et les nouvelles colonnes COUVERTURE et PARENT.
  2. Créer les consultations dans CS_TEMPLATE : une ligne par type, les créneaux par demi-journée (LUN_AM … VEN_PM).
  3. Relier chaque consultation à son secteur : colonne CS de l'onglet SECTEURS. Sans ce lien, le panneau de placement ne met pas en tête les MAR du secteur.
  4. Saisir les affectations mensuelles avec les nouveaux codes, à partir du mois d'effet, à l'aide de la table de correspondance de la Phase A.
  5. Désactiver les anciens secteurs (ACTIF = N) — seulement quand l'affichage des semaines de l'ancien hôpital n'est plus nécessaire, ou une fois le rendu adapté (voir le constat du §02).
  6. Ctrl+Maj+R et passer aux contrôles ci-dessous.

06Phase D — Contrôles après bascule

ContrôleCe qu'on doit voir
Légende du planning Les nouveaux secteurs, avec leurs couleurs — la légende se construit à partir des secteurs réellement utilisés : il faut au moins une affectation saisie.
Le « + » clignotant Retirer quelqu'un d'un secteur couvert un jour ouvré : un « + » doit apparaître. Vérifier aussi qu'un secteur non couvert ne flashe pas.
Boutons « Déplacer vers » Le volet latéral propose les nouveaux secteurs actifs.
Excel du vendredi Un bandeau par grand secteur, les sous-secteurs dessous, chaque nouvelle consultation sur sa ligne. Ouvrir le fichier dans le vrai Excel, pas seulement l'aperçu.
Historique Une semaine d'avant la bascule s'affiche toujours correctement (planning et Excel).
Diagnostic Lancer le diagnostic de l'onglet Maintenance : aucun message nouveau.
Journal Aucun avertissement « code secteur inconnu → VOLANT » : il signalerait une affectation saisie avec un code non créé ou mal orthographié.

07Pièges connus

  • Basculer avant la Phase B : les nouveaux secteurs existeraient à l'écran mais ne flasheraient jamais — le pire des états, parce qu'il est silencieux.
  • Renommer un code « pour faire propre » : jamais (§02).
  • Re-générer les gardes 2027 : jamais. Le déménagement n'est pas une raison — les gardes ignorent les secteurs.
  • Un secteur créé sans AFF n'apparaît pas dans le sélecteur d'affectation : c'est voulu (cas DVI), mais y penser si un secteur « n'apparaît pas ».
  • L'espace en tête des libellés Excel de CS_TEMPLATE est voulu (il décale le texte dans la cellule) : ne pas le « corriger ».
  • La bascule en cours de mois : les affectations sont mensuelles, l'écran mélangerait deux organisations le même mois.
